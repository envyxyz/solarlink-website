## Causes found

- **The hero image is not slow.** `hero-768.avif` is 19 KB, preloaded with `fetchpriority=high`, matches the rendered candidate (`sizes` gives 768 on a 412 px phone), is requested at 40 ms and Lighthouse reports it discoverable. Observed LCP is 0.4 to 1.0 s; the 3 s is Lighthouse's simulated slow-4G model.
- **JavaScript is what the model charges.** Variants of the built HTML: no scripts gives home LCP 2.04 s and TBT 0; the 160 KB of async React and Next scripts adds about 1.3 s of LCP and 230 ms of TBT, because they load and hydrate before first paint, competing with CSS, the 98 KB font and the image. Inner pages whose LCP is the lead paragraph pay the same (1.66 s without scripts).
- **Fix** (`scripts/post-export.mjs`, run by `pnpm build`): the scripts load from a tiny inline loader 500 ms after `load`. JS size is unchanged (`js-size.mjs` reads the loader list: 160.1 KB of 182.0). Cost: the quote slider and phone menu go live about 0.5 s after load; links work before. The h1, hero image and CSS are untouched.
- **Font.** The 98 KB Mona Sans face sits on the FCP path (removing it: FCP 1.5 to 0.9 s). next/font emits no preload in a static export. A manual preload cut FCP to 0.8 s but moved hydration inside the TBT window (home perf 83), so it was left out.
- **CLS.** The shift (0.03) was the h1 wrapping to an extra line when Mona Sans (`wdth 125`) replaced the stock Arial fallback, which cannot follow the width axis; everything below moved 45 px. A first guess (breadcrumb and chip row wrapping) was wrong and reverted. Fix: a display-only fallback face, Arial at 118.43% (measured width ratio 1.138 times the stock 104.08%), `--font-display` in `tokens.css`, noted in `DESIGN.md`. With a 300 ms font delay at 412 and 360 px the shift on 5kw, outlets and growatt falls from 0.034 to 0.00004 (Playwright layout-shift observer; not re-run through Lighthouse).
- **RSC prefetch 404s are a Windows-only artefact.** Next 16.4 `export/index.js` builds segment names from `path.relative()`; on Windows the backslash is not replaced by `convertSegmentPathToStaticExportFilename`, so `__next.$c$slug.__PAGE__.txt` is written as `__next.$c$slug\__PAGE__.txt` (a nested folder). Linux and CI builds write the dotted name, so Cloudflare is not affected. `post-export.mjs` renames the nested files so local runs match. `/get-quote/` is still prefetched but has no page yet (content, not export).
