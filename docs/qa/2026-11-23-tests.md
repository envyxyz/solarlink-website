## Findings

- **F1 Performance and LCP over budget.** Home: LCP element is the hero image `hero-768.avif` (`src/components/home/Hero.tsx:46`, preload at `:18`), LCP 3.46 s and TBT 509 ms. Inner pages: LCP 2.5 to 3.3 s; the image is the `PageHero` img (`src/components/pages/PageHero.tsx:24`), on the outlet page the lead paragraph. Needs a real-hosting run (Cloudflare compression and caching) before acting; likely contributors are client JS on every page (TBT) and the hero image weight.
- **F2 Prefetch 404s.** Next requests `/<route>/__next.$c$slug.__PAGE__.txt?_rsc=...` (for example `/outlets/`, `/get-quote/`, `/resources/`), but the export wrote `__next.$c$slug/__PAGE__.txt` (nested). They log console errors and cost Lighthouse best practices (100 to 96). Probably Windows-build or webpack specific; rebuild on Linux/CI with Turbopack before treating as a bug. Content-side: `/get-quote/` is also prefetched but the segment file is missing.
- **F3 Small CLS on inner pages.** `/solar-systems/5kw/` 0.034 (shift in `PageHero` stage, `src/components/pages/PageHero.tsx:70`) and `/outlets/lahore/` 0.031 (body container, `src/components/site/InnerPage.tsx:86`). Budget is 0.
- **F4 Reviews link placeholder.** Home renders `<a href="[confirm with client]">` in preview (`src/components/home/Reviews.tsx:26`, value from `googleReviewsUrl` in content). Production check-content already blocks this.
- No accessibility findings; no `src/` changes were made.
